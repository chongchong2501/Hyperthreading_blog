如果你刚打开 DSH 的插件市场，大概率会跟我当初一样——眼花缭乱。

插件市场里几十个插件，标题、版本号、简介，密密麻麻排在一起。到底该装哪个？装了之后怎么用？出了问题怎么办？

这篇文章就是为了解决这个问题。

我自己在 DSH 里装过十几个插件，有些用了几天就卸了，有些装了三个月还在用。最后留下这 9 个。下面我把每个插件做什么、适合谁、为什么留到现在，都说清楚。

## 插件市场怎么逛

先解决第一个问题：入口在哪？

打开 DSH，找到插件市场（dsh-market）。进去之后你会看到几个 Tab：发现、主题、收藏、已安装、高级、任务。

"发现"是浏览所有可安装的插件，支持搜索。搜索框里可以打关键词，比如"通知""终端""记忆"，找到你想找的功能。"主题"是界面相关的插件，比如背景、配色。"收藏"是你标记过想装但还没装的。"已安装"就是你当前装了什么。"高级"有更多筛选和管理选项，"任务"是插件相关的后台任务状态。

安装一个插件很简单：在发现页找到目标插件，点安装，等几秒钟就装好了。装完之后状态栏会显示"启用中"和"已是最新"，旁边有个卸载按钮。

如果你记不住某个插件是干嘛的，插件卡片上有"添加备注"按钮，可以写几句自己的话。我一般写"这玩意儿用来 XXX 的"，回头查的时候比翻插件简介快。

一个小建议：新手别贪多。插件不是越多越好，装了十几个之后你会发现有些功能重叠，有些插件之间会打架。按需装、勤更新，比一口气全装完强。

## 9 个插件全景速览

我把这 9 个插件分成四类：界面体验、会话数据、上下文推理、可靠性监控。

| 分类 | 插件 | 一句话说明 |
|------|------|------------|
| **界面体验** | `deepseek-harness-background` | 自定义背景、毛玻璃、暗色遮罩 |
| | `dsh-better-sidebar` | 侧边栏工作台：文件、终端、Git、子代理 |
| | `dsh-model-visibility` | 模型菜单过滤，零侵入 |
| | `reasoning-slider` | 推理强度滑块，Codex 风格 |
| **会话数据** | `dsh-archived-chats` | 按工作区批量归档，全文搜索 |
| **上下文推理** | `dsh-context` | 上下文仪表盘、可视化、命令 |
| | `dsh-better-reasoning-effort` | 按模型优化推理参数 |
| **可靠性监控** | `dsh-llm-retry-settings` | API 报错自动重试 |
| | `dsh-usage-statistics-panel` | Token 用量统计与趋势 |

下面逐个说。

## deepseek-harness-background

::github{repo="HaoyueQin/deepseek-harness-background"}

这个插件干的事很直接：让 DSH 的界面有自己的背景。

你可以上传本地图片，或者粘贴一个图片链接，整个界面就会用那张图做背景。不透明度、明暗自适应遮罩、面板透明度、毛玻璃效果、壁纸模糊程度，都能调。调的时候实时预览，调好之后设置会持久化保存，下次打开还在。

我一开始装它是觉得默认白底看久了有点腻。调完之后确实舒服一些，但不影响阅读——背景是暗化处理过的，不会跟文字打架。

它还带一个隐藏彩蛋：DeepSeek 官网风格的会话时间线导航轨。就是会话列表旁边多了一条时间线，可以设书签，点一下就跳到对应的会话。如果你会话多，这个功能挺方便的。

## dsh-better-sidebar

::github{repo="omdsh-dev/DSH-better-sidebar"}

这个插件做的事情稍微大一点：把侧边栏从"看个会话列表"升级成一个完整工作台。

侧边栏里直接可以编辑和渲染文件、跑终端、看 Git 状态、管理子代理。而且它支持第三方插件注册新的 Tab，也就是说以后有别的插件想往侧边栏里塞东西，也能塞进来。

### 文件渲染和编辑

DSH 原生是聊天为主，如果你想在聊天旁边看一眼文件、改两行代码，原生是不行的——你得切到外部编辑器。这个插件在侧边栏里直接嵌了一个文件渲染器，支持 Markdown、代码高亮、JSON 格式化，甚至能直接编辑。你在聊天里让 AI 改了一段配置，侧边栏里立刻就能看到改了什么，不用跳来跳去。

### 终端

这个插件在侧边栏里嵌了一个完整的终端，你可以直接跑命令、看输出、执行脚本。配合文件编辑功能，基本上一个工作流能闭环：AI 写代码 → 侧边栏看代码 → 侧边栏跑测试 → 发现问题 → 让 AI 改 → 再看。全程不切窗口。

### Git 集成

侧边栏里直接能看到当前仓库的状态——哪些文件改了、哪些提交了、有没有冲突。不用开 Git GUI，不用跑命令行，扫一眼侧边栏就知道代码在什么状态。

### 子代理管理

DSH 支持开子代理并行干活，但原生管理界面不太直观。这个插件在侧边栏里做了一个子代理列表，每个代理的状态、进度、日志都能看，还能直接跟子代理对话。

### 第三方 Tab 注册

这个插件本身是一个 Tab 注册平台。其他插件可以往侧边栏里塞自己的面板，不需要改 DSH 核心代码。这意味着以后有插件想加个数据库面板、加个 API 调试器、加个日志查看器，只要注册一个 Tab 就行，侧边栏自动多出一个标签页。

我装它的原因很朴素：不想在 DSH 和编辑器之间反复切窗口。以前是 DSH 聊天、编辑器写代码、终端跑命令、Git 客户端看状态，四个窗口来回切。现在侧边栏里直接能看文件、跑命令、看 Git、管子代理，省了至少三个窗口。

装了这个之后我试了几天，确实效率有提升。尤其是调试的时候，AI 改了代码，侧边栏立刻能看到 diff，跑个测试也在侧边栏里，发现问题直接跟 AI 说"刚才那个改动不对，改回来"——全程没切窗口。

## dsh-model-visibility

::github{repo="Lzh3070/dsh-model-visibility"}

如果你用过第三方模型，大概率会遇到模型菜单太长的问题。几十个模型排在一起，每次选模型都得滑半天。

这个插件就是解决这个问题的：按渠道或按模型，逐条隐藏或显示模型选择菜单里的条目。支持实时搜索，可以按渠道批量隐藏/显示，也可以一键恢复全部。

它的设计我觉得挺有意思：零侵入。它不改你的 Provider 配置，只写自己的隐藏列表。这意味着你隐藏了某个模型之后，如果那个模型正在使用，会话不会中断——只是菜单里不再显示而已。这比直接改配置文件安全得多。

我装它的原因是模型太多了。我同时配了几个渠道，菜单里几十个模型，每次选模型都要往下滑好几屏。隐藏掉不常用的之后，菜单清爽了一大截。

## reasoning-slider

::github{repo="qjcnmd/dsh-reasoning-slider"}

这个插件很小，功能也单一：在模型选择器里加一个推理等级滑块，拖动就能切换推理档位。

以前选推理强度是下拉菜单或者选项卡，这个插件改成了滑块，Codex 风格。拖动一下，low / medium / high 随便切。

先说它好看在哪里。这个滑块的设计是跟模型选择器融为一体的，不是生硬地加一个控件在旁边。滑块的样式、颜色、动效都跟 DSH 的 UI 风格保持一致，看起来像是原生的一部分。尤其是那个拖动手感——平滑、有阻尼感、松手即停，不是那种滑到边缘又弹回来的廉价交互。

而且它支持不同推理档位之间的过渡动画。从 low 拖到 high，滑块不是直接跳过去，而是有一个流畅的滑动过程，中间经过 medium 的时候有个微妙的停顿感，就像你拨动一个物理旋钮。这个细节做好了，整个交互体验就完全不一样。

视觉上还有一个小亮点：滑块会根据当前推理强度显示不同的颜色。low 是冷色调，high 是暖色调，中间有渐变过渡。不是那种刺眼的颜色跳跃，是柔和的渐变，看着舒服。

功能上，它支持所有主流模型的推理档位配置，包括 DeepSeek 自家的模型和第三方模型。你拖一下，配置就保存了，下次打开还在。

我装它是因为拖滑块比点下拉框快。尤其是我经常需要在不同会话之间切换不同的推理强度，一个滑块比下拉菜单顺手。而且说实话，这个滑块确实好看——放在模型选择器旁边，整个界面的精致感就上来了。

## dsh-archived-chats

::github{repo="Ultronen/dsh-archived-chats"}

这个插件解决的是会话管理的问题。工作区里会话多了之后，找东西、清理东西都很麻烦。

它可以按工作区批量归档符合条件的会话。归档之后不是丢了——你可以按工作区浏览，也可以全文搜索。每个归档会话都有原生只读预览，想看一眼内容不用打开。

还有几个功能做得细：历史版本可恢复为副本，不会覆盖当前版本；标签和备注，给归档打标签方便分类；JSON + Markdown ZIP 导出，怕丢数据的时候可以把归档打包带走；带保护快照的回收站，误删了能找回；空间分账，看哪些归档占了多少空间；Origins & Branches，查看 fork 和子代理树的只读关系。

最重要的一点：所有数据都留在本机，保存在 `$DSH_HOME/plugin-data/archived-chats/` 目录下。不搞云端同步，隐私这块不用担心。

## dsh-context

::github{repo="bowenliang123/dsh-context"}

这个插件是解决"上下文黑盒"问题的，也是我装过之后觉得最有价值的插件之一。

你知道 DSH 的上下文里有什么吗？系统提示词、历史对话、注入的知识库内容、压缩后的摘要、工具调用的结果……这些东西平时是看不见的，但 AI 的回答质量跟它们直接相关。

dsh-context 给你一个上下文仪表盘，可以看到上下文的分类组成、每类内容的详情、演进趋势、压缩和注入事件、各种统计。还有一个 `/context` 命令可以直接在会话里调用，加上一个 Context 浏览器。

### 上下文仪表盘

打开之后你会看到一个清晰的分类视图：哪些内容来自系统提示词，哪些是历史对话，哪些是注入的知识库，哪些是压缩后的摘要。每个分类都有占比、大小、数量。这个视图的价值在于——你终于知道上下文里到底装了什么。

以前遇到 AI 回答不好，第一反应是"模型不行"。但很多时候问题出在上下文：系统提示词太长、历史对话太杂、注入的内容跟当前问题无关。dsh-context 让你能直接看到这些，而不是靠猜。

### /context 命令

这个命令可以在会话里直接调用，比如输入 `/context` 就能看到当前会话的上下文详情。输入 `/context --brief` 可以看简略版，`/context --stats` 可以看统计。这个命令的好处是实时——它显示的是当前这一刻的上下文状态，不是缓存的旧数据。

### Context 浏览器

这个功能是 dsh-context 最强的部分。它让你可以逐个查看上下文里的每一条内容：系统提示词的完整文本、每一条历史消息的完整内容、每一个工具调用的输入和输出、每一次压缩事件的细节。你可以展开看、折叠收起、搜索关键词。

举个例子，你发现 AI 突然开始答非所问。打开 Context 浏览器，搜索相关关键词，你会发现上下文中有一条早期的错误信息被 AI 反复引用。这条信息可能来自三天前的一个对话，早就该被清理掉了。在 Context 浏览器里你找到了它，知道了问题出在哪，就能有针对性地让 AI 忽略这条信息或者清理上下文。

### 压缩与注入追踪

dsh-context 会记录每一次上下文压缩事件——什么时候触发的、压缩了多少内容、压缩前后的差异是什么。还有每一次注入事件——注入了什么内容、来自哪里、占了多大空间。这些记录帮你理解上下文的演变过程。

还有一个统计面板，显示上下文的各种指标：总大小、各分类占比、缓存命中率、压缩率、注入频率。这些数据帮你判断上下文是不是太满了、需不需要清理。

我装它的主要原因是想了解 AI 为什么这么答。以前遇到 AI 回答不好，只能猜测是模型问题还是上下文问题。现在打开 dsh-context 一看，问题一目了然：要么是上下文里塞了太多无关内容，要么是某条历史消息误导了 AI，要么是系统提示词跟当前任务不匹配。知道原因之后，就能有针对性地调整。

这个插件的版本更新也比较频繁，一直在加新功能和优化体验。如果你觉得上下文是个黑盒让你抓狂，这个插件值得第一个装。

## dsh-better-reasoning-effort

::github{repo="HaoyueQin/dsh-better-reasoning-effort"}

这个插件是给第三方模型用户准备的。

DSH 原生支持调整推理强度，但有些第三方供应商的模型需要更细致的配置——比如按模型分别设置思考强度和输入模式。

这个插件让你在官方"模型"页的卡片里直接编辑这些参数。而且它不是瞎猜——它会融合知识库和 `/models` 端点的信息，给出建议，还标注置信度。意思是它告诉你"我建议这个模型用 medium 推理强度，置信度 85%"，你直接采纳或者调一下就行。

我装它是因为我用了好几个第三方模型，每个模型的推理参数不一样，手动调太麻烦。这个插件把这件事自动化了一大半。

## dsh-llm-retry-settings

::github{repo="zeng6125-rgb/dsh-llm-retry-settings"}

这个插件解决一个很烦人的问题：API 偶发报错。

用 LLM 的时候经常遇到 HTTP 400、401、429 之类的报错。有些是暂时的，重试一下就好了，但你得手动重发。

这个插件让你在设置页直接调整重试次数、退避策略和抖动参数。还可以勾选哪些错误码应该重试。

它默认补入了 INVALID_REQUEST 这个错误码，意味着碰到这个错误会自动重试，不用你手动加。另外，OpenAI thinking 模式下 HTTP 400 reasoning_text 报错也是开箱即自动重试。这个场景我太熟了——thinking 模式经常莫名其妙报 400，以前得手动重试好多次，现在自动处理了。

## dsh-usage-statistics-panel

::github{repo="HaoyueQin/dsh-usage-statistics-panel"}

最后一个：用量统计面板。

这个插件提供完整的用量统计：26 周活跃度热力图，看你哪周用得勤；按日 Token 趋势和缓存命中率曲线，看每天的消耗；模型用量环形图和明细，看哪个模型用得最多；时间范围筛选，按周按月看；汇总卡片，关键指标一眼看完。

它还支持历史会话回扫和无损重建，意思是就算这个插件刚装上，之前用过的会话的统计数据也能补回来。

我装它是因为想知道自己一个月烧了多少 Token。不看不知道，看了才知道原来缓存命中率能到这么高——或者这么低。知道数字之后，用模型的时候就有节制了。

## 我的安装顺序建议

新手装插件别一口气全装。我的建议是分三步：

1. **先装这三个。** dsh-context——上下文是 DSH 最核心的黑盒，先搞明白；dsh-llm-retry-settings——API 报错是最常见的痛点，先解决；dsh-better-sidebar——侧边栏工作台效率提升最明显。这三个解决的是日常最痛的三个问题。
2. **按需装这三个。** dsh-archived-chats——会话多了再装；dsh-model-visibility——模型菜单长了再装；dsh-usage-statistics-panel——想知道花多少钱了再装。这三个的价值跟你的使用规模相关，用得少的时候装了也没用。
3. **个性化。** deepseek-harness-background——想看腻了白底再装；dsh-better-reasoning-effort——用第三方模型多了再装；reasoning-slider——习惯拖滑块再装。这三个是锦上添花，不装也不影响使用。

## 几个实用提醒

> 以下五点是我踩坑之后总结出来的，装插件之前建议扫一眼。

**插件冲突。** 装了几个之后如果侧边栏异常或者设置页报错，大概率是插件之间冲突了。先卸载最近装的那个，看看是不是它的问题。我遇到过两次，都是某个插件跟侧边栏插件打架。

**版本更新。** 插件市场里"已是最新"这个标记不要忽视。DSH 本身在更新，插件有时候需要跟着更新才能正常工作。隔一段时间看看有没有可更新的。

**备份。** 插件配置和会话归档分开存。别只依赖插件的回收站——插件本身可能出问题。dsh-archived-chats 的 ZIP 备份功能在这种时候有用。

**安全。** 第三方插件装之前看看源码和权限声明。别盲装来源不明的。特别是那些要求额外权限的插件，多问一句"它要这个权限干嘛"。

**常见误区。** 插件不是越多越好。我试装过十几个，最后留下这 9 个。有些插件功能重叠，装了反而增加维护负担。

## 最后

DSH 插件生态最值钱的地方不是功能多，而是它让每个人都能把工具调成自己最顺手的形状。

你看，同样的 DSH，有人装了这 9 个插件，有人可能一个都没装，用法完全不一样。这不是谁对谁错，是不同人的需求不同。

如果你刚接触 DSH 插件，先从第一步那三个装起。用熟了之后再去逛发现页，收藏那些感兴趣的插件。收藏多了之后，你大概就清楚自己的需求了。

如果你也自己写插件，欢迎在社区贡献。插件生态是社区一起养出来的，每多一个有用的插件，后面的人就少踩一个坑。
